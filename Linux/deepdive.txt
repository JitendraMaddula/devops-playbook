    OS = kernel+sys libraries + shell(bash or zsh) = Distribution

Folder Structure:
    Symbolic Links (Less Significant)
        /sbin -> /usr/sbin	System binaries for administrative commands (linked to /usr/sbin).
        /bin -> /usr/bin	Essential user binaries (linked to /usr/bin).
        /lib -> /usr/lib	Shared libraries and kernel modules (linked to /usr/lib).
    Important System Directories
        /boot	Stores files needed for booting the system (not relevant in containers).
        /usr	Contains most user-installed applications and libraries.
        /var	Stores logs, caches, and temporary files that change frequently.
        /etc	Stores system configuration files.
    User & Application-Specific Directories
        /home	Default location for user home directories.
        /opt	Used for installing optional third-party software.
        /srv	Holds data for services like web servers (rarely used in containers).
        /root	Home directory for the root user.
    Temporary & Volatile Directories
        /tmp	Temporary files (cleared on reboot).
        /run	Holds runtime data for processes.
        /proc	Virtual filesystem for process and system information.
        /sys	Virtual filesystem for hardware and kernel information.
        /dev	Contains device files (e.g., /dev/null, /dev/sda).
    Mount Points
        /mnt	Temporary mount point for external filesystems.
        /media	Mount point for removable media (USB, CDs).
        /data	Likely your mounted volume from Windows (C:/ubuntu-data).

sed - Stream Editor - Find/Replace, Print, Delete etc
    -- Find and Replace Strings
        sed 's/<old-string>/<new-string>/ig' <file-name> --> To find and replace the string [File does not get modified]
            s -- Substitute
            g -- global
            i -- Ignore Casing
        sed -i 's/<old-string>/<new-string>/ig' <file-name> --> To insert the changes to the file
        sed '4s/<old-string>/<new-string>/ig' <file-name> --> To find and replace only on the 4th line
        sed '4,8s/<old-string>/<new-string>/ig' <file-name> --> To find and replace from 4th line to 8th line
        sed '4,$s/<old-string>/<new-string>/ig' <file-name> --> To find and replace from 4th line to end of the file
    -- Delete Lines
        sed '4d' <file-name> --> To delete the 4th line of the file
        sed '4,8d' <file-name> --> To delete from 4th line to 8th line of the file
        sed '4,$d' <file-name> --> To delete from 4th line to end of the file
        sed '4d;8d' <file-name> --> To delete 4th line and 8th line of the file
    -- Print Lines
        sed -n '4p' <file-name> --> To Print the 4th line of the file
        sed -n '4,8p' <file-name> --> To Print from 4th line to 8th line of the file
        sed -n '4,$p' <file-name> --> To Print from 4th line to end of the file
        sed -n '4p;8p' <file-name> --> To Print 4th line and 8th line of the file
    -- Backup option
        sed -i.bkp '4,8d' <file-name> --> To delete and insert changes from 4th line to 8th line of the file and also create a backup of the original with name <original-file-name>.bkp
    -- Insert Lines using Sed
        sed -i '4 a\<text>' <file-name> --> To insert text after the 4th line of the file
        sed -i '$ a\<text>' <file-name> --> To insert text at the end of the file

        The sticky bit is a special permission setting on a directory that ensures users can only delete or rename files they personally own, even if the directory itself is writable by everyone.
        To add it: chmod +t /path/to/directory
        To remove it: chmod -t /path/to/directory

Daemon Process --> A helpful background worker that runs completely invisibly, unattached to any terminal screen, just waiting to handle continuous system chores (like managing network connections or printing).
Zombie Process --> A dead process that has finished its task but is stuck hovering in the system's memory list because its "parent" process hasn't officially acknowledged its completion yet.
Orphan Process --> A child process that keeps right on running even after the parent process that created it has suddenly crashed or closed.
Linux booting process --> 
    BIOS / UEFI (Hardware Check) --> The computer wakes up, runs a quick diagnostic to make sure all physical parts (like RAM and keyboard) are working, and searches for a drive to boot from.
    MBR / EFI (Boot Sector) --> A tiny piece of code stored at the very beginning of your hard drive that simply points the computer to the main boot program.
    GRUB (Bootloader) --> The menu screen that lets you choose which operating system you want to start, which then grabs the Linux core (the kernel) and loads it into the computer's memory.
    Kernel --> The central brain of Linux takes control, manages the hardware, and mounts your main hard drive so the system can actually read and write files.
    Init / Systemd --> The very first true program to run (always assigned process ID 1) that starts up all your background tasks, network connections, and eventually your graphical login screen.

Difference between archivng and zipping and compressing
Archiving (e.g., tar): This is the process of combining multiple files and directories into a single file (an archive). It does not reduce the file size. It is simply a container.
Zipping/Compressing (e.g., gzip, zip, bzip2): This is the process of applying an algorithm to mathematically reduce the file size to save disk space or bandwidth.

Difference between init process, sshd process and systemd process
    •	init: The traditional first process (PID 1) started by the kernel that sequentially launches all other system services using basic scripts.
    •	systemd: The modern replacement for init (also PID 1) that boots the system, manages services in parallel, and comprehensively handles system resources.
    •	sshd: A standard background network daemon, managed by systemd or init, that listens for and handles incoming secure remote login connections.

Ssh connection is being delayed, how do you troubleshoot it?
    1. Diagnose with Verbose Mode
        Before making any changes, find out exactly which step is causing the lag. Run your SSH command with the verbose flag (-v or -vvv for maximum detail):
        ssh -v username@hostname    
    2. Disable Reverse DNS Lookups (Server-Side)
        The most common cause of SSH delays is the server attempting to perform a reverse DNS lookup on your client's IP address. If the server cannot resolve the IP, it will wait until the request times out before proceeding.
    3.  Check Network and Firewall Latency
        If the connection is still slow after tweaking the SSH configurations, the issue might be network-related.
        Run a ping or traceroute to the server to check for high latency or dropped packets.
