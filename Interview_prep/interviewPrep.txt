Folder Structure:
    Symbolic Links (Less Significant)
        /sbin -> /usr/sbin	System binaries for administrative commands (linked to /usr/sbin).
        /bin -> /usr/bin	Essential user binaries (linked to /usr/bin).
        /lib -> /usr/lib	Shared libraries and kernel modules (linked to /usr/lib).
    Important System Directories
        /boot	Stores files needed for booting the system (not relevant in containers).
        /usr	Contains most user-installed applications and libraries.
        /var	Stores logs, caches, and temporary files that change frequently.
        /etc	Stores system configuration files.
    User & Application-Specific Directories
        /home	Default location for user home directories.
        /opt	Used for installing optional third-party software.
        /srv	Holds data for services like web servers (rarely used in containers).
        /root	Home directory for the root user.
    Temporary & Volatile Directories
        /tmp	Temporary files (cleared on reboot).
        /run	Holds runtime data for processes.
        /proc	Virtual filesystem for process and system information.
        /sys	Virtual filesystem for hardware and kernel information.
        /dev	Contains device files (e.g., /dev/null, /dev/sda).
    Mount Points
        /mnt	Temporary mount point for external filesystems.
        /media	Mount point for removable media (USB, CDs).
        /data	Likely your mounted volume from Windows (C:/ubuntu-data).

Merge Conflict
    A merge conflict occurs when Git cannot automatically figure out which changes to keep when combining two branches. The most common reasons are:
        •	Same-line edits: Two branches modify the exact same line(s) in the same file differently.
        •	Modify vs. Delete: One branch updates a file, while the other branch completely deletes that same file.
        •	File creation collision: Both branches create a new file with the exact same name but different content.
    Resolve the conflict manually, then:
        git add .
        git commit

Rebase -> git rebase <branch_name>: Apply changes of the current branch on top of another branch. This can lead to a cleaner commit history compared to git merge.

Reset -> Moves the branch pointer to a previous commit.
    Soft Reset -> Removes the last commit but keeps changes staged.
    Mixed Reset -> Removes the last commit and un-stages changes.
    Hard Reset -> Deletes the last commit and all associated changes.

Key difference between restore, reset, revert
    git restore works in working directory and staging
    git reset works in all 3 and also rewrites history
    git revert works in all 3 without rewriting history but adds a new commit

Difference between interpreter and compiler:
  •	Compiler: A compiler translates your entire program into a finished, ready-to-run file all at once before it ever starts running.
  •	Interpreter: An interpreter translates and runs your code one single line at a time while the program is actively running.

Difference between ant and maven
•	Approach: Ant is procedural, meaning you have to write explicit, step-by-step scripts telling it exactly how to build the project. Maven is declarative and uses 'convention over configuration.' Because Maven has a standardized project structure, it already knows how to build the project—you just tell it what you need it to do.
•	Dependency Management: Maven automatically downloads and manages third-party libraries and their sub-dependencies via a central repository. With Ant, you traditionally have to download, store, and link those library files manually.

***ANSIBLE***
Ansible is an open-source tool used for configuration management, application deployment, along with infrastructure orchestration.

Architecture -> Modules -> Plugins -> Controller Machine -> Inventory

Hosts file -> Grouping Hosts in hosts file

Playbook -> are list of tasks written in yaml format that gets executed on host machines. managed using ansible-playbook command

PLAY RECAP Variables -> PLAY RECAP section shows execution statistics for each host.
ok=X -> Tasks that executed successfully without making changes
changed=Y -> Tasks that executed successfully AND made changes to the system
unreachable=Z -> Hosts that Ansible couldn't connect to
failed=A -> Tasks that failed during execution
skipped=B -> Tasks that were skipped due to conditions
rescued=C -> Tasks that failed but were handled by rescue blocks
ignored=D -> Failed tasks that were explicitly ignored

Idempotency -> is the property that running a playbook or task multiple times produces the same result as running it once, ensuring no unintended changes occur after the initial application.

Ansible Register and Debugging:
Ansible register is a way to capture the output from task execution and store it in a variable.
Debug will print the values that are stored in the register Variables

Ansible tags
Using tags, we can run specific task or play in a playbook

Static inventory -> A manually maintained file (YAML) listing hosts and groups, updated by hand.
Dynamic Inventory-> A script or plugin that fetches host/group data from an external source (cloud API, CMDB, etc.) at runtime.

Default location of host file/inventory is /etc/ansible/hosts

Ansible Roles -> Standardized directory structures (tasks/, vars/, templates/) that allow you to define complex automation logic once and reuse it across multiple playbooks and projects.managed using ansible-galaxy command

Ansible Roles Standardized directory structure -> tasks/main.yml -> handlers/main.yml -> defaults/main.yml -> vars/main.yml -> templates/ -> files/ -> meta/main.yml -> tests/
